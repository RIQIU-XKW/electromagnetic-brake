# emmc_test —— eMMC(SD1 / FatFs)文件逻辑宿主机测试

把 **真实的 `bsp/emmc/emmc.c`** 编到 PC 上，底下换成内存里的一段字节，验证记录与回读
逻辑。不需要板子、不需要 SD 卡，几秒钟出结果。

```
powershell -ExecutionPolicy Bypass -File tools\emmc_test\run.ps1
```

## 编的是什么

| 角色 | 文件 |
|---|---|
| **被测代码** | `vitis2/app923/src/bsp/emmc/emmc.c`（真实的那份） |
| FatFs 替身 | `stub/ff.h` + `host_ff.c`（内存文件系统，512 KB） |
| OSAL 替身 | `host_osal.c`（互斥量空实现，单线程测试） |

**真实的 FatFs（`third_party/xilffs/`）不参与这个测试** —— `stub/` 目录在 `-I` 里排在
前面，所以 `#include "ff.h"` 拿到的是桩。这样测的完全是本工程自己的文件逻辑。

## 覆盖了什么

1. **新建文件**先写表头，记录数从 0 开始，表头以 `\r\n` 收尾。
2. **追加 + 计数**：40 条之后快照里的 `Records` / `Bytes` 与文件实际内容一致。
3. **关掉再打开**（`Rewind = 0`）：不重写表头，重新数一遍还是 40 条；继续追加会累加。
4. **一行横跨两次读块**时仍能正确数行 —— 桩的 `f_read` 故意**按 512 字节短读**
   （`HostFs_SetShortReadChunk`），压的就是"按块找 `\n` 会漏行"这条路径。这个坑是写
   这版代码时真踩到的：原先按 512 字节分块处理行，文件偏移不落在扇区边界上时就会数错。
5. **掉电写了一半的尾巴**（文件末尾没有换行）：打开时会被补一个 `\r\n` 收尾，
   而且**不计入**记录数（`Records` 仍是 3 而不是 4）。
6. **字段数不对的废行**（4 个字段 / 11 个字段）回读时被跳过，不会混进曲线。
   ⚠ 正常记录现在是 **10 列**（`t_ms,i1..i5,vbus,speed,x_mm,laser_mv`，9 个逗号），
   所以"10 字段"那条用例已经改成 11 字段 —— 别再用 10 字段当废行。
7. **分批回读**：100 条记录用 7 行一批拉完，**不重不漏**；`More` 语义正确；
   起点越界返回 0 行 + `more=0`（而不是报错或回垃圾）；从中间起读的内容和原始记录逐字节一致。
8. **写失败**（`FR_DISK_ERR`，模拟卡被拔）：返回 `EMMC_ERR_IO`，快照记下 FatFs 的错误码，
   而且 `Records` **不增加** —— 不能把没写进去的算成写成功了。

## 本测试**不**覆盖什么（这些只能上板验）

- **SD 控制器本身**：`xsdps` 驱动、SD1 的时钟与 MIO、eMMC 的初始化（CMD0/CMD1…）。
- **cache 一致性**：`XPAR_XSDPS_1_IS_CACHE_COHERENT = 0`，SD 控制器不是缓存一致的。
  代码里把走 DMA 的缓冲做成"静态 + 32 字节对齐"就是为这个，但**对不对只有上板才知道**。
- **真并发**：FatFs 默认不可重入（`FF_FS_REENTRANT = 0`），串行化完全靠 `bsp/emmc` 里
  那把 osal 递归互斥量。测试是单线程顺序调用，互斥量是空实现 —— 锁的**顺序**（暂存锁 →
  FatFs 锁）是设计上保证的，但"两个任务真同时进来会不会死锁"得在板子上跑。
- **eMMC 的实际写入速度与寿命**：100 Hz 下每秒写约 4 KB，能不能长期扛住要看卡。
- **service/emmc 那一层**（队列、攒批、CSV 拼行、EMCxxx 命令）：本测试只到 `bsp/emmc`。
  那一层由编译 + `tools/led_test` 同款的代码审查覆盖，端到端只能上板跑。

## 文件

```
run.ps1            编译 + 运行（ASCII only：PS 5.1 按 ANSI 读 .ps1）
test_emmc.c        断言（7 节）
host_ff.c          内存文件系统（FatFs 接口的桩实现）
host_osal.c        OSAL 桩（互斥量空实现 + 日志桩）
stub/ff.h          FatFs 接口声明（只声明 emmc.c 用到的那些）
stub/xil_printf.h  log.h 需要
```

## 为什么桩里故意少声明接口

`stub/ff.h` 只声明 `bsp/emmc/emmc.c` 真正用到的那几个 FatFs 函数。少一个声明，
`emmc.c` 里多调一个不存在的函数就会**当场编译失败**，比等到链接期才发现好。
